# Как у нас делается контент

```
Предложение (Discord) → Разбор → Диздок → Задачи (issues) → Разработка (PR) → Тестовый сервер → Релиз
```

## 1. Предложение

Идеи игроки и команда пишут в **форум-канал предложений** в Discord: одна идея - одна ветка. Ветка получает тег «На рассмотрении», под ней голосуют и обсуждают.

На разборе `heads` меняют тег:

| Тег | Что дальше |
|---|---|
| Принято | Создаётся issue по шаблону «Предложение» со ссылкой на ветку, ссылка на issue - в ветку |
| Отклонено | В ветке пишется причина, ветка закрывается |
| Уже есть / дубль | Ссылка на существующее |
| Реализовано | Ставится, когда фича в релизе |

В GitHub попадают только принятые идеи - репозиторий не засоряется, а игрокам не нужен аккаунт GitHub.

## 2. Разбор

Принятое предложение - это issue. На разборе решают:

- **Мелочь** (баг, спрайт, текст, число) - сразу в работу, диздок не нужен;
- **Крупное** - нужен [диздок](design/README.md), назначается автор диздока.

## 3. Диздок

Пишется по [шаблону](design/_TEMPLATE.md) и проходит через PR. Одобрение кого-то из `heads` - решение принято. В диздоке обязательно: владелец, заместитель, происхождение (наше или порт), как выключить и удалить. Подробно - в [design/README.md](design/README.md).

## 4. Задачи

Одобренный диздок режется на issues по шаблону «Задача»: по одной на код, прототипы, спрайты, карту, локализацию. Каждая ссылается на диздок и имеет исполнителя.

## 5. Разработка

- Наш код и ресурсы - только в папках `_LP`.
- Правки в файлах Starlight и SS14 - минимальные, помечены `// LP edit start` / `// LP edit end`.
- Портированный код остаётся в своём namespace (`_Corvax`, `_GoobStation`…), запись в `LEGAL.md` обязательна.
- В PR - ссылка на диздок (или «мелочь, без диздока») и блок `:cl:` для чейнджлога.
- Если реализация отличается от диздока - диздок обновляется в том же PR.

## 6. Тест и релиз

PR мёржится в `master` → проверка на тестовом сервере → переносится в `stable` с релизом. После релиза фича записывается в [реестр](features.md), ветка предложения в Discord получает тег «Реализовано».

## Уход из команды

Перед уходом передайте свои фичи: поменяйте владельца в [реестре](features.md) и в диздоках. Раз в месяц `heads` сверяют реестр - фичи ушедших без передачи уходят заместителям или получают статус «На поддержке».
