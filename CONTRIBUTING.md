# Как внести вклад в Lost Light

Спасибо, что хотите помочь! Здесь собрано всё, что нужно знать перед первым PR. Если что-то непонятно - спрашивайте в [Discord](https://wiki.lost-paradise.space/discord), это нормально.

## С чего начать

1. Соберите проект по инструкции из [README](README.md#сборка).
2. Посмотрите [доску задач](https://github.com/orgs/Lost-Paradise-Project/projects/7): в виде «Бэклог» лежит всё, что можно взять. Взяли задачу - назначьте себя исполнителем.
3. Прочитайте, [как у нас делается контент](docs/process.md): предложение → диздок → задачи → PR.
4. Для крупной фичи (новая механика, роль, раса, порт системы) сначала нужен одобренный [диздок](docs/design/README.md). Багфиксы, спрайты, тексты и правки чисел идут без диздока.

Идеи без готовой задачи предлагайте в форуме предложений в Discord, а не через issue.

## Куда класть файлы

Сборка основана на [Starlight](https://github.com/ss14Starlight/space-station-14), а тот - на [Space Station 14](https://github.com/space-wizards/space-station-14). Чтобы обновления Starlight вливались без боли, наш контент живёт отдельно:

| Что | Куда |
|---|---|
| C# | `Content.*/_LP/` |
| Прототипы | `Resources/Prototypes/_LP/` |
| Спрайты, звуки | `Resources/Textures/_LP/`, `Resources/Audio/_LP/` |
| Гайдбук | `Resources/ServerInfo/_LP/` |
| Русская локализация нашего контента | `Resources/Locale/ru-RU/_LP/` |

Портированный из других сборок контент остаётся в своей папке (`_Corvax`, `_Goobstation` и т. п.), а в [LEGAL.md](LEGAL.md) добавляется запись о лицензии.

## Правки в чужих файлах

Файлы Starlight и SS14 меняйте только если без этого никак, и как можно меньше. Каждую правку помечайте:

```csharp
// LP edit start - зачем правка
...
// LP edit end

var x = 1; // LP edit
```

```yaml
# LP edit start
...
# LP edit end

  name: something # LP edit
```

В XAML - `<!-- LP edit -->`. Строки `using` в C# не помечаем. В YAML пометку не ставьте отдельным элементом списка (`- # LP edit`): такая строка превращается в пустой элемент и ломает прототип.

Чужие пометки (`Starlight edit`, `Goobstation` и т. п.) не трогаем. Если правку в чужом файле портировали из другой сборки, она сохраняет пометку источника (`DEN edit`, `Corvax` и т. п.), а не `LP edit`.

## Код

- Никаких строк для игрока прямо в коде: только `Loc.GetString("ключ")` в C# и `{Loc 'ключ'}` в XAML.
- Значения CVar меняются в пресете `Resources/ConfigPresets/_LP/LP.toml`, а не в значениях по умолчанию в коде.
- Секреты (токены, пароли, вебхуки) в репозиторий не попадают - только в конфиг на сервере.
- Следуйте [стилю кода SS14](https://docs.spacestation14.com/en/general-development/codebase-info/conventions.html).

## Локализация

- Строки нашего контента пишите сразу по-русски в `Resources/Locale/ru-RU/_LP/`. Папку `en-US/_LP` не создаём.
- Перевод строк Starlight и SS14 обновляется скриптом `Tools/localize`. Файлы `ru-RU` вне `_LP` правьте только чтобы исправить перевод: файл без пары в `en-US` скрипт удалит.
- Проверить разметку гайдбука можно скриптом `Tools/localize/check_guidebook.py`.

## Спрайты и звуки

- У каждого ассета должны быть лицензия и автор: в `meta.json` для спрайтов, в `attributions.yml` для звуков.
- По умолчанию ассеты идут под [CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/). Ассеты с неясной лицензией или под запретом на использование не принимаем.

## Pull request

- Один PR - одна тема. Большие изменения проще проверять по частям.
- Заполните шаблон PR: ссылка на диздок (или «мелочь»), `Closes #N` для задачи, медиа, если изменение видно в игре.
- Блок `:cl:` с записью для чейнджлога - если изменение заметно игрокам. Список изменений собирает бот.
- Перед PR соберите проект и запустите игру хотя бы локально.
- Проверки стиля (`pre-commit.ci`) запускаются сами и при необходимости докоммитят исправления в ваш PR. Локально их можно включить так: `pip install pre-commit`, затем `pre-commit install`.
- Ревьюеров назначает [CODEOWNERS](.github/CODEOWNERS). Решение о мёрже принимают `heads` и мейнтейнеры.

Общие правила оформления - в [руководстве SS14 по PR](https://docs.spacestation14.com/en/general-development/codebase-info/pull-request-guidelines.html).
